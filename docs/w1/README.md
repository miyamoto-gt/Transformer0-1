## やったこと

4トークン × 次元 d の入力から `Q, K, V` を作り、`Q @ K.T` で 4×4 のスコア行列を得て、softmax したあと `V` と掛ける。フレームワークは使わず numpy のみ。

![alt text](img/image.png)

真ん中の `(4, 4)` が「4トークン × 4トークンの相性表」で、Attention の本体はここだけ。前後の `(4, 8)` は入口と出口で、**形が一致している**ため出力をそのまま次の層に渡せる。

検証したのは以下の3点。

- softmax 後の各行の合計が 1 になるか
- `scores` を `raw / √d / d` の3通りで割ったとき、分布の尖り方がどう変わるか
- 次元 `d` を 8 → 64 に変えたとき、その傾向が保たれるか

尖り具合の指標には `P.max(axis=-1).mean()` を使った。4トークンなので、1.0 なら1つだけを見ている状態、0.25 なら全部を均等に見ている状態。

```
  raw        P.max=0.9258  sum=[1. 1. 1. 1.]

  scores std: 512.03
  raw        P.max=1.0000  sum=[1. 1. 1. 1.]

  /d         P.max=0.9991  sum=[1. 1. 1. 1.]
```

![alt text](img/image-1.png)

### 各行の合計は常に 1

全9パターンで `sum=[1. 1. 1. 1.]`。分布が飽和していようと潰れていようと、softmax は必ず 100% を配り切る。チェック項目クリア。

### `√d` だけが次元に振り回されない

| | d=8 | d=64 | 変化 |
|---|---|---|---|
| 割らない | 0.542 | 0.926 | 尖っていく |
| **÷√d** | **0.425** | **0.568** | **ほぼ不変** |
| ÷d | 0.321 | 0.291 | 潰れていく |

割らなければ次元を上げるほど one-hot に近づき、`d` で割れば逆に一様分布（0.25）へ潰れる。**どちらもモデルサイズを変えると性格が変わってしまう。**

つまり `√d` は「ちょうどいい値だから」選ばれているのではなく、**`d` を変えても分布の尖り具合が保たれる唯一のスケール**だから選ばれている。

---

## ハマった点: 割り算だけでは救えない

d=64 で試したとき、`√d` で割っても `P.max = 0.9999` になり予想が外れた。原因は `scores` の除算ではなく **`W` の初期化スケール**だった。

`W = rng.normal(size=(d, d))` のまま使うと `Q, K` の各要素の標準偏差が `√d = 8` になる。その内積を取ると `scores` の標準偏差は `d^1.5 = 512`。これを 8 で割ってもまだ 64 残るので、softmax にとっては十分に飽和する。

![alt text](img/image-2.png)

`W` を `1/√d` でスケールすると `scores std` が **512.03 → 8.46**（理論値 512 と 8 にほぼ一致）に収まり、理論通りの結果が出た。

初期化を外した状態では **3通りとも `P.max ≈ 1.0`**。`√d` で割っても、`d` で割ってさえ 0.9991。割り方の選択そのものが無意味になる。

> **`√d` 除算は「Q・K の要素分散が 1」という前提の上に成り立つ後処理でしかない。**
> 前提を保証しているのは初期化のほうで、前提が崩れればどう割っても救えない。

教科書には「`√d` で割る」としか書かれておらず、前提のほうは書かれない。実装して初めてぶつかった。

## 導出メモ

各成分が独立に平均 0・分散 1 の `d` 次元ベクトル `q, k` について、

```
Var(q·k) = Σ Var(q_i k_i) = d      →  標準偏差 = √d
```

なので `√d` で割ると分散が 1 に戻る。`d` で割ると `1/d` になり割りすぎ。

softmax の上位2つの比は `P1/P2 = exp(z1 - z2)` で、**差だけで決まり指数で効く**。今回 `scores` に `43.34` と `-77.47` が現れた行では差が約 120 あり、`exp(120) ≈ 10^52`。倍精度の有効桁を超えるため、小さいほうは完全に 0 になる。

初期化なしの場合は `Q, K` の分散が `d` なので、内積の分散は `d^3`、標準偏差 `d^1.5`。d=64 で 512。

---

## 学んだことの整理

1. **表面**: `scores` を `√d` で割ると softmax の尖りが抑えられる
2. **その下**: `√d` は内積の標準偏差そのもの。だから `d` に依存しない唯一のスケールになる
3. **さらに下**: この処方箋は初期化が分散 1 を保っていることが前提。前提が崩れれば無効

3 は予想を外して原因を追わないと出てこなかった。

## 補足: 各関数の解説（Day 1 進捗メモより）

### 1. Attention の全体像

Attention は、各トークンが「どの他のトークンを見るべきか」を重みで決める仕組みです。

入力が x で、各位置の表現が d 次元だとすると、次のような計算をします。

- Q = xW_q
- K = xW_k
- V = xW_v

ここで、Q は「問い合わせ」、K は「参照キー」、V は「実際に取り出す値」です。

そして、各位置 i と j の関係性を計算します。

score(i, j) = Q_i · K_j

これを行列で表すと、

scores = Q K^T

になります。

次に、これを softmax で正規化して重み P を作ります。

P = softmax(scores)

最後に、各位置の出力は重み付きの値の総和で決まります。

output_i = Σ_j P_ij V_j

つまり、各位置は「自分と似ている/関連している位置の情報」を重みで集めて、より豊かな表現を作ります。

### 2. softmax 関数の役割

#### 関数名
softmax(z)

#### 何をしているか
この関数は、各行ごとに重みを正規化します。

一般的な softmax は次の式です。

softmax(s)_i = exp(s_i) / Σ_j exp(s_j)

ただし、実装では最大値を引いてから exp を計算しています。

softmax の安定化:

s' = s - max(s)

e = exp(s')

softmax(s) = e / Σ e

#### なぜ必要か

Attention のスコアは大きくなりやすく、exp の計算でオーバーフローしやすいためです。
最大値を引くと、値の大きさを揃えつつ、正規化した重みを作れます。

つまり、重要なのは「各位置に対する重みを確実に 0 から 1 の範囲で表し、合計が 1 になるようにすること」です。

### 3. init_weights 関数の役割

#### 関数名
init_weights(d, rng, scale=True)

#### 何をしているか
この関数は、Q / K / V を作るための重み行列をランダムに初期化します。

W_q, W_k, W_v の各要素は、サイズが d × d の正規分布乱数です。

W_q, W_k, W_v = random_normal(d, d)

scale が True のときは、

s = sqrt(d)

として重みを d の平方根で割っています。

W = random / sqrt(d)

#### なぜこの割り算が必要か

Q と K の内積は、次元が大きいほど大きくなりやすいです。

score = Q K^T

そのままでは softmax に入る値が極端に大きくなり、ほとんど一つの位置に重みが集中してしまいます。
そのため、通常の Attention では次のようにスケーリングします。

score = Q K^T / sqrt(d)

このコードでは、それを「初期化時に重みを小さくすることで近い効果を出す」形になっています。

### 4. attention 関数の役割

#### 関数名
attention(x, W_q, W_k, W_v, div=None)

#### 何をしているか
この関数が Attention の本体です。

1. 入力 x から Q, K, V を作る

Q = xW_q
K = xW_k
V = xW_v

2. 各位置のスコアを計算する

scores = Q K^T

3. 必要なら割る値でスケーリングする

if div is not None:
    scores = scores / div

4. softmax を施して重み P を得る

P = softmax(scores)

5. 重みを使って V を集約する

output = P V

#### 最終的な意味

各トークンの出力は、他トークンの情報を「どこをどれだけ見るか」の重みで加算したものです。

output_i = Σ_j P_ij V_j

これがまさに Transformer の核心的な処理であり、各トークンが文脈を参照できるようにする仕組みです。

### 5. compare_divisors 関数の役割

#### 関数名
compare_divisors(d, rng, scale=True)

#### 何をしているか
この関数は、スケーリングの方法を変えたときに、Attention の挙動がどう変わるかを比較しています。

比較しているのは次の3つです。

- raw: 割らない
- /sqrt(d): d の平方根で割る
- /d: d で割る

つまり、

scores = Q K^T / divisor

の divisor を変えて、どれが安定しやすいかを確認しています。

#### ここで見る指標

- scores.std(): スコアのばらつき
- P.max(axis=-1).mean(): 各行で最も大きい重みの平均
- P.sum(axis=-1): 各行の重みの合計

この実験を通して、「スケーリングが小さすぎると重みが弱くなり、大きすぎると偏る」ことを感覚的に理解できます。

### 6. Day 1 で分かったこと

今日の理解のポイントは次の通りです。

- Attention は、トークン同士の関連度を計算して重みを作る仕組みである
- Q / K / V は、それぞれ問い合わせ・参照キー・値を表す
- スコアは QK^T で計算される
- softmax により、重みが 0 以上 1 未満の値で、各行の和が 1 になる
- sqrt(d) で割るのは、スコアが大きくなりすぎるのを防ぐためである
- 最後に重みと V を掛け合わせることで、文脈に基づく表現が作られる

この最小実装を通して、Transformer の中核が「単なる行列計算」ではなく、
「どこを重視するかを重みで決める設計」であることが見えてきました。
