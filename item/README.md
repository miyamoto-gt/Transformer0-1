# Day 1 進捗: Attention の基礎を理解する

## 今日の目標

Transformer の中心にある Attention を、最小限のコードで理解することを目標にしました。
今回の実装では、「入力から Query / Key / Value を作り、どの位置同士が関係しているかを計算し、その重みで情報を集約する」という流れを体験しています。

---

## 1. Attention の全体像

Attention は、各トークンが「どの他のトークンを見るべきか」を重みで決める仕組みです。

入力が x で、各位置の表現が d 次元だとすると、次のような計算をします。

- Q = xW_q
- K = xW_k
- V = xW_v

ここで、Q は「問い合わせ」、K は「参照キー」、V は「実際に取り出す値」です。

そして、各位置 i と j の関係性を計算します。

score(i, j) = Q_i · K_j

これを行列で表すと、

scores = Q K^T

になります。

次に、これを softmax で正規化して重み P を作ります。

P = softmax(scores)

最後に、各位置の出力は重み付きの値の総和で決まります。

output_i = Σ_j P_ij V_j

つまり、各位置は「自分と似ている/関連している位置の情報」を重みで集めて、より豊かな表現を作ります。

---

## 2. softmax 関数の役割

### 関数名
softmax(z)

### 何をしているか
この関数は、各行ごとに重みを正規化します。

一般的な softmax は次の式です。

softmax(s)_i = exp(s_i) / Σ_j exp(s_j)

ただし、実装では最大値を引いてから exp を計算しています。

softmax の安定化:

s' = s - max(s)

e = exp(s')

softmax(s) = e / Σ e

### なぜ必要か

Attention のスコアは大きくなりやすく、exp の計算でオーバーフローしやすいためです。
最大値を引くと、値の大きさを揃えつつ、正規化した重みを作れます。

つまり、重要なのは「各位置に対する重みを確実に 0 から 1 の範囲で表し、合計が 1 になるようにすること」です。

---

## 3. init_weights 関数の役割

### 関数名
init_weights(d, rng, scale=True)

### 何をしているか
この関数は、Q / K / V を作るための重み行列をランダムに初期化します。

W_q, W_k, W_v の各要素は、サイズが d × d の正規分布乱数です。

W_q, W_k, W_v = random_normal(d, d)

scale が True のときは、

s = sqrt(d)

として重みを d の平方根で割っています。

W = random / sqrt(d)

### なぜこの割り算が必要か

Q と K の内積は、次元が大きいほど大きくなりやすいです。

score = Q K^T

そのままでは softmax に入る値が極端に大きくなり、ほとんど一つの位置に重みが集中してしまいます。
そのため、通常の Attention では次のようにスケーリングします。

score = Q K^T / sqrt(d)

このコードでは、それを「初期化時に重みを小さくすることで近い効果を出す」形になっています。

---

## 4. attention 関数の役割

### 関数名
attention(x, W_q, W_k, W_v, div=None)

### 何をしているか
この関数が Attention の本体です。

1. 入力 x から Q, K, V を作る

Q = xW_q
K = xW_k
V = xW_v

2. 各位置のスコアを計算する

scores = Q K^T

3. 必要なら割る値でスケーリングする

if div is not None:
    scores = scores / div

4. softmax を施して重み P を得る

P = softmax(scores)

5. 重みを使って V を集約する

output = P V

### 最終的な意味

各トークンの出力は、他トークンの情報を「どこをどれだけ見るか」の重みで加算したものです。

output_i = Σ_j P_ij V_j

これがまさに Transformer の核心的な処理であり、各トークンが文脈を参照できるようにする仕組みです。

---

## 5. compare_divisors 関数の役割

### 関数名
compare_divisors(d, rng, scale=True)

### 何をしているか
この関数は、スケーリングの方法を変えたときに、Attention の挙動がどう変わるかを比較しています。

比較しているのは次の3つです。

- raw: 割らない
- /sqrt(d): d の平方根で割る
- /d: d で割る

つまり、

scores = Q K^T / divisor

の divisor を変えて、どれが安定しやすいかを確認しています。

### ここで見る指標

- scores.std(): スコアのばらつき
- P.max(axis=-1).mean(): 各行で最も大きい重みの平均
- P.sum(axis=-1): 各行の重みの合計

この実験を通して、「スケーリングが小さすぎると重みが弱くなり、大きすぎると偏る」ことを感覚的に理解できます。

--

## 6. Day 1 で分かったこと

今日の理解のポイントは次の通りです。

- Attention は、トークン同士の関連度を計算して重みを作る仕組みである
- Q / K / V は、それぞれ問い合わせ・参照キー・値を表す
- スコアは QK^T で計算される
- softmax により、重みが 0 以上 1 未満の値で、各行の和が 1 になる
- sqrt(d) で割るのは、スコアが大きくなりすぎるのを防ぐためである
- 最後に重みと V を掛け合わせることで、文脈に基づく表現が作られる

この最小実装を通して、Transformer の中核が「単なる行列計算」ではなく、
「どこを重視するかを重みで決める設計」であることが見えてきました。
