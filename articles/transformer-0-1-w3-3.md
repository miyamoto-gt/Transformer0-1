## はじめに

[前回](https://zenn.dev/)は、3つの壊し方がすべて同じ場所(ユニグラム水準の3.3)で停滞し、曲線では区別できないことを見た。切り分けには、データの目視と層別の勾配ノルムという2つの道具が要った。

今回は残り2つである。前回とは症状が逆になる。

| 壊し方 | 何が起きるか |
|---|---|
| #6 データを2,000文字に限定 | trainは下がるがvalが上がる |
| #3 causal mask削除 | **train も val も下がり続ける** |

#6は教科書的な過学習で、valを見ていれば気づける。問題は#3である。**数値に一切の異常が出ない。** しかも325 iterのあいだ、基準と完全に同じ曲線を描く。

先に#6を見て「valが役に立つ場合」を確認してから#3に進む。

## #6 学習データを2,000文字に絞る

Karpathyのrecipeにある「小さいデータで過学習させてみる」の逆版である。わざと過学習を起こす。

trainの先頭2,000文字だけを使う。全体は約100万文字なので0.2%になる。

```python
common.run(m, tag="overfit_2000", train_data=common.train[:2000])
```

パラメータは215,873個。2,000文字に対して100倍以上の容量がある。block_sizeが128なので、取れる開始位置は1,872通り。600 iter × batch 32 = 19,200サンプルを取るので、**平均10回以上は同じ箇所を見る**計算になる。

### 測り方に落とし穴があった

最初、間違ったグラフが出た。trainもvalも両方上昇する、過学習とは似ても似つかない形である。

原因は、`estimate_loss`に2,000文字を渡していなかったことだった。

```python
common.run(m, train_data=common.train[:2000])   # 学習は2,000文字
    ↓
l = estimate_loss(m)      # 測定は train 全体(100万文字)
```

これだと`train`の線が「学習に使っていない99.8%」を含んで測られる。実質valと同じものを2本描いていたことになる。過学習は「学習に使ったデータ」と「使っていないデータ」の差なので、前者を正しく測らないと現れない。

**分離は最初から始まっている。** iter 25の時点ですでにtrain 2.96 / val 3.24と差がある。#3のような潜伏期間はない。

ここまでが前置きになる。#6は厄介ではあるが、**valを見ていれば検出できる**。iter 75で底を打ち、以降は上がる。early stoppingという対処法も確立している。

## #3 causal maskを削除する

Transformerで次の文字を予測するとき、位置tは自分より後ろを見てはいけない。答えを先に見ることになるからである。

これを防ぐのがcausal maskになる。attentionのスコアに`-inf`を入れ、softmax後の確率を0にする。

```python
self.register_buffer("mask", torch.tril(torch.ones(block_size, block_size)).bool())
...
scores = scores.masked_fill(~self.mask[:T, :T], float("-inf"))
```

`tril`は下三角行列なので、こういう形になる。

```
        見られる位置 →
        0      1      2      3
位置0  True  False  False  False
位置1  True  True   False  False
位置2  True  True   True   False
位置3  True  True   True   True
```

これを全部Trueにすると、maskが機能しなくなる。

```python
for b in m.blocks:
    b.attn.mask.fill_(True)
```

W2のコードは書き換えず、モデルを作った後にbufferの中身だけ差し替える形にした。

### なぜこれが致命的か

入力`x`と正解`y`の関係を思い出してほしい。

```
x: '\nANGELO:\nAnd she wil'
y:  'ANGELO:\nAnd she will'
```

`y[t]`は`x[t+1]`と同じ文字である。maskを外すと位置tが`x[t+1]`を参照できるので、**答えが入力の中にある**ことになる。

素直に考えれば、lossは即座に0に近づくはずである。

### ところが何も起きない

![mask削除](/images/w3/no_mask.png)

| iter | 基準 | mask削除 |
|---|---|---|
| 100 | 2.6113 | 2.6065 |
| 200 | 2.5144 | 2.5069 |
| 300 | 2.4400 | 2.4320 |
| **325** | 2.4245 | 2.3914 |

300 iterまで、**基準とほぼ同じ値**だった。差は0.01以下。グラフを重ねても区別できない。

実は最初、200 iterで実験していた。そのときの結論は「mask削除の影響なし」である。何度確認してもmaskは正しく無効化されているのに、lossが変わらない。バグを疑って、maskが本当に効いているか調べる時間を使った。

答えは単純で、**iter数が足りなかった**だけだった。

### 350 iterから崩れ落ちる

600 iterまで延ばすと、こうなる。

![基準とmask削除の比較](/images/w3/compare_mask.png)

| iter | 基準 | mask削除 |
|---|---|---|
| 325 | 2.4245 | 2.3835 |
| **350** | 2.4174 | **2.2164** ← 分岐 |
| 400 | 2.3941 | 1.1226 |
| 500 | 2.3045 | 0.1205 |
| 600 | **2.2395** | **0.0472** |

**基準の47分の1**である。前回の3000 iterで到達した1.83すら、iter 375の時点で追い抜いた。

そして重要なのは、**trainもvalも一緒に下がっている**ことである。0.0449 / 0.0480でほぼ重なっている。#6のような分離は一切ない。過学習の兆候もない。

数値だけ見れば、これは大成功になる。

## なぜ325 iterも潜伏するのか

ここが面白いところだった。答えが見えているのに、なぜすぐ使わないのか。

仮説はこうである。**カンニングするにも学習が要る。**

attentionは重み付き平均である。位置tの出力は、他の位置のベクトルを混ぜ合わせた値になる。

```
出力 = Σ (重み_i × value_i)
```

位置t+1だけに重み1.0を置ければ、答えがそのまま取り出せる。だがそれは**学習して獲得する重み付け**である。初期状態では128個の位置に均等に分散している。

つまり答えの寄与は1/128 ≈ 0.008。**他の127個に埋もれていて、信号にならない。**

### 測ってみた

仮説を確かめるため、「位置tが位置t+1に向けるattentionの重み」を測る関数を書いた。

```python
@torch.no_grad()
def attn_to_next(m, layer=0):
    x, _ = get_batch(val, block_size, batch_size)
    h = m.tok_emb(x) + m.pos_emb(torch.arange(block_size))
    b = m.blocks[layer]
    _, P, _ = b.attn(b.ln1(h))
    T = block_size
    diag = P[:, :, torch.arange(T - 1), torch.arange(1, T)]
    return diag.mean().item()
```

`P`の形は`(batch, head, T, T)`。`[:, :, t, t+1]`が求める値になる。

まず学習前を測る。

```
mask あり: 0.0
mask なし: 0.00778   (1/128 = 0.0078125)
```

maskありは0。未来なので`-inf`でマスクされ、softmax後に0になる。当然である。

**mask なしは0.00778で、1/128 = 0.0078125とほぼ完全に一致した。** 完全に一様である。仮説どおり、外した直後は答えを取り出せる状態にない。

学習前のloss差も`4.319901` vs `4.319870`で、0.00003しかなかった。

### 学習中の推移

25 iterごとに記録した。

| iter | val loss | attn→t+1 | 一様比 |
|---|---|---|---|
| 0 | 4.3258 | 0.0078 | 1.0 |
| 100 | 2.6065 | 0.0084 | 1.1 |
| 200 | 2.5033 | 0.0102 | 1.3 |
| **300** | **2.4320** | **0.0195** | **2.5** |
| 325 | 2.3914 | 0.0336 | 4.3 |
| 350 | 2.1935 | 0.0683 | 8.8 |
| 400 | 1.0645 | 0.1855 | 24 |
| 600 | 0.0480 | 0.2770 | **35** |

**iter 300の時点で、attnはすでに2.5倍に育っていた。** ところがlossは2.4320で、基準の2.4400とほぼ同じ。グラフ上ではまったく区別できない。

2軸で描くとこうなる。

![lossが平らな間にattentionが育つ](/images/w3/compare_attn.png)

赤(attn)の立ち上がりが、青(loss)の崩壊に**先行している**。灰色は基準のloss。赤が点線(一様の水準)を離れ始めるのは250付近、青が灰色から離れるのは325以降である。

### 伸び方が非線形

| 区間 | attnの伸び |
|---|---|
| 0→100 | ×1.08 |
| 100→200 | ×1.21 |
| 200→300 | ×1.91 |
| **300→400** | **×9.5** |
| 400→600 | ×1.49(飽和) |

300→400で一気に加速した。ここで自己増強のループが回り始める。

```
t+1への注意が少し強まる
  → 答えが少し見える
  → lossが少し下がる
  → 「t+1を見ると得だ」という勾配が強まる
  → 注意がさらに集中する
  → ...
```

正のフィードバックなので、一度回り始めると止まらない。そして0.27前後で飽和する。

### 学習が止まったように見えても

これが今回一番の収穫だった。**lossが平らな区間でも、内部では回路が組み上がっている**ことがある。

「位置+1を見る」という重み付けは、`pos_emb`から位置の関係を読み取ってqueryとkeyの対応を作る作業である。文字の内容とは無関係な、純粋に位置に基づくパターン。この回路が完成するまでは効果が出ず、完成した瞬間から一気に効く。

grokkingや相転移と呼ばれる現象に近い形だと思う。

## 検出する方法は1つしかない

ここまでの状況を整理する。

- lossは下がり続けている
- valも一緒に下がっている
- trainとvalは重なったまま
- 基準の47分の1という驚異的な数値
- エラーは一切出ない

**数値からは異常が検出できない。** 普段信頼している指標が、全部「正常」を指している。

残る方法は1つである。**実際に文章を生成させること。**

### 生成させてみる

生成時は文章がまだ存在しないので、1文字ずつ作っていく。未来が存在しない以上、**カンニングできない**。

```
基準 (val 2.24)                          mask削除 (val 0.047)

Thes dreoun, hind youn ancorseshe be     H
fabuty, in thourd sowe therds            HHVe
ineancoup ance theer wine, sonoule       HHHHLHH
tore, vet. sor's dintcrdlin thes         HL
kndd my agnat then anyou ans not         HHHH
doue the not moke nrall;                 HLN
I seld; Ther                             HHL
```

基準は`no` `four` `these` `wine` `not` `my` `then`といった実在語やそれに近い綴りを出した。カンマ・ピリオド・セミコロンの使い方、`I seld;`のような1人称+セミコロンの構造も掴んでいる。

mask削除のほうは`H`と改行の羅列である。英語の構造を何も学んでいない。

**lossが47分の1のモデルのほうが、圧倒的に劣る。**

### なぜこうなるか

maskを外したモデルは「隣を見る」という戦略だけを学んだ。それで十分にlossが下がるからである。

文脈から次を予測する能力は、**学ぶ必要がなかったので学んでいない**。生成時にその戦略が使えなくなると、何も持っていない状態で書かされることになる。

訓練時と本番で条件がずれている、という話になる。causal maskの役割は「学習時に生成時と同じ条件を再現すること」だった。それを外すと、学習は簡単になるが本番で通用しない。

## 6つを並べてみる

Week3で試した6つの結果である。

| # | 壊し方 | iter 600 (val) | trainとval | 検出方法 |
|---|---|---|---|---|
| — | 基準 | 2.2395 | 重なる | — |
| #1a | lr ×100 | 2.9645 | 重なる | 終盤の傾き |
| #1b | lr ×1000 | 3.3410 | 重なる | 曲線全体 |
| #2 | シャッフル | 3.3403 | 重なる | データの目視 |
| #3 | mask削除 | **0.0472** | 重なる | **生成** |
| #4 | 初期値×10 | 2.4658 | 重なる | 学習前の測定 |
| #5 | 残差削除 | 3.3432 | 重なる | 層別の勾配 |
| #6 | データ2,000字 | 5.7113 | **分離** | train/valの差 |

**trainとvalが分離したのは#6だけ**である。他の5つはすべて重なったまま壊れている。

「valを見ていれば安心」という前提は、6つ中5つで成り立たなかった。

## Week3でわかったこと

**1. 症状が同じでも原因は別々。** #1(lr=1.0)、#2、#5はすべてユニグラム水準で停滞する。切り分けには追加の測定が要る。

**2. lossが低いほど良いとは限らない。** #3は基準の47分の1を達成しながら、生成は明確に劣る。

**3. 打ち切る位置で結論が変わる。** #3は325 iterまで基準と一致するので、200 iterで止めれば「影響なし」と誤断する。実際に一度そうなった。

**4. lossが平らでも内部は動いている。** #3のattnは、何も起きていないように見える区間で1.3倍 → 2.5倍と育っていた。

**5. 予想はよく外れる。** 4層なら残差は要らない、残差削除で勾配消失、発散といえばNaN、mask削除は即座に効く。全部外れた。

診断の手順として整理するとこうなる。

```
loss が 3.3 付近で停滞
  │
  ├─ 1. x と y を目視              ← 1秒
  ├─ 2. 層別の勾配ノルム
  └─ 3. 学習曲線の全体

loss が順調に下がっている
  │
  ├─ val だけ上がる → 過学習
  └─ 両方下がる → 生成させてみる   ← これしか方法がない
```

最後の「生成させてみる」が、今回一番学んだことになる。**数値がすべて正常を指していても、成果物を見なければ分からないことがある。**

## おわりに

3回に分けて、Transformerを6通りに壊した記録を書いた。

当初の目的は「症状 → 原因」の対応表を作ることだった。実際に作ってみると、1つの症状に複数の原因が対応する場合があり、表だけでは足りないと分かった。切り分けの手順まで用意して、ようやく道具になる。

そして、自分が何を信頼していたかも見えた。val lossを見ていれば大丈夫だと思っていたのに、6つ中5つでそれが通用しない。バグは「lossが下がらない」形でだけ現れるわけではなかった。

次は評価設計を扱う予定である。今回valだけを頼りにしていた部分を、もう少し丁寧に組み立てる。
