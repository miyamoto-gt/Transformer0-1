## 共通のルール

### 過学習の判定基準

- val CE の最小値を更新しない評価点が **5回** 続き、かつ
- 現在の val CE が最小値より **0.02以上** 高い(ノイズ 0.004 の5倍)

ステップ2の早期終了(patience)にもそのまま使う。

### 物差し

- 主は CE、正解率は副。判定と比較は CE で行う
- 記事で見せるときは PPL(= exp(CE))を併記してもよい
- 記録する項目:val 最小値 / val 最小の iter / そのときの gap / 最終 val / エポック数

### エポック数

- 1 iter で見る文字数 = batch_size × block_size = 32 × 32 = 1,024
- エポック数 = max_iters × 1,024 ÷ 学習データの文字数

## ステップ1:過学習を起こす

### 土台(`data_0.1`)

- train_frac 0.1(100,385 文字)・3000 iter(約31エポック)・d_model 64
- val の底 2.2909(iter 2400)、3000 iter の時点では判定まであと1点(4回)
- 「ぎりぎり過学習しない」状態。#1・#3・#4 はここから1つだけ変える

### 4つの原因

| # | 原因 | 変えたもの | tag | val の底 | 判定 | 状態 |
|---|---|---|---|---|---|---|
| 2 | 訓練データが少ない | train_frac 0.1 → 0.01 | `data_0.01` | 2.66(iter 450) | iter 1200 | 完了 |
| 3 | 学習回数が多すぎる | max_iters 3000 → 6000 | `data_0.1_6000` | 2.29(iter 2400) | iter 3150 | 完了 |
| 1 | モデルが複雑すぎる | d_model 64 → 128 | `model_d128` | 2.25(iter 1200) | iter 1950 | 完了 |
| 4 | 特徴量が多すぎる | 区間IDを入力に追加 | `feat_1000` | 2.38(iter 1350) | iter 2100 | 完了 |

### #4 特徴量が多すぎる(案B)

**ねらい**:各サンプルに「テキストのどのあたりから切り出したか」の番号(区間ID = 開始位置 ÷ 1,000)を付けて入力に足す。train では丸暗記の手がかりになるが、val では内容と対応しないので役に立たない。

**決めたこと**

- 区間IDは1サンプルに1つ。埋め込み (B, d) を (B, 1, d) にして、32文字すべてに同じベクトルを足す
- val にも val 内の開始位置から区間IDを付ける
- 区間の数 = train と val の長いほう ÷ 区間の幅 + 1(幅 1,000 なら 112)
- W2 の `model.py` は変えず、継承した FeatureModel を `feat_model.py` に作る

**手順(すべて完了)**

| | 内容 |
|---|---|
| 1〜3 | FeatureModel を作る(B=2 と B=32 で形を確認) |
| 4 | get_batch が開始位置 ix を返す(`data_0.1` と完全一致) |
| 5 | 区間IDを run() と evaluate に通す(`interval_width` 引数) |
| 6 | 埋め込みの初期化を `torch.random.fork_rng()` で囲み、乱数のずれを防ぐ |
| 7 | ずれていないことを確認(対策あり:一致/なし:不一致) |
| 8 | evaluate を区間IDのリストを受け取る形にし、`interval_mode`("pos" / "noise")を追加。回帰テストで `data_0.1`・`feat_1000` と完全一致 |

**結果**

| | data_0.1 | feat_noise | 幅 10,000 | feat_1000 |
|---|---|---|---|---|
| train の区間ID | なし | ランダム | 位置から(12区間) | 位置から(112区間) |
| val の底 | 2.2909 / 2400 | 2.2879 / 3000 | 2.3215 / 1350 | 2.3837 / 1350 |
| 判定 | 届かない | 届かない | iter 2850 | iter 2100 |
| 最終 train CE | 1.4356 | 1.5204 | 1.4617 | 1.4588 |
| 最終 val CE | 2.3151 | 2.2879 | 2.3505 | 2.4393 |
| 最終 gap | 0.88 | 0.77 | 0.89 | 0.98 |
| 最終 val acc | 0.411 | 0.407 | 0.402 | 0.386 |

**分かったこと**

- 区間IDを位置から付けると過学習に転んだ。区間を細かくするほど悪い(12区間 < 112区間)
- 予想に反し、train CE は速くならなかった。悪化は val 側で起きた
- 同じベクトルをランダムに付けると悪化しなかった → 原因は「ベクトルを足したこと」ではなく「train でだけ通用する手がかりに頼ったこと」
- ランダムな区間IDは gap を最も小さくした(0.77)。入力にノイズを加える正則化と同じ働き(ただし最終 val の差 0.003 はノイズの範囲)
- 記事用の一文:不要な特徴が有害なのは、存在するからではなく、モデルが train でそれに頼れてしまうからである

## ここまでで分かったこと

- 「gap が開く」ことと「val が上がる」ことは別。過学習と判断するのは後者
- val が1点だけ上がることはある。1点の上昇だけでは過学習と判断しない
- データが少ないほど、val の底は高く・早く来て、底の後の悪化も急になる
- 「1エポックで底を打つ」という仮説は外れ。実際は 24〜46 エポックまで val は改善した。よく出る規則を学び尽くしてから、特定の並びの丸暗記が始まる
- d_model を上げると、底は低く・早く来るが、その後の悪化が速い。ちょうど良いところで止めれば、大きいモデルの方が良い
- 過学習すると、val acc は横ばいのまま val CE だけが上がる(自信満々の間違い)。0.01 では学習前やでたらめ(ln 65)より悪くなった
- 乱数:seed は列の出発点。乱数を余分に引くと、学習バッチの ix がずれる。専用の Generator や fork_rng で切り離す
- 回帰テスト:コードを変えるたびに、前と同じ設定で完全一致するかを確かめる。一致すれば、その変更が学習に影響していないと言える

## ステップ2:対策を1つずつ実装

### 方針

- 主な対象は `model_d128`(train_frac 0.1・3000 iter・d_model 128)。底 2.2484 / iter 1200、判定 iter 1950、最終 2.4737
- 対策は1つずつ。実験ファイルは `fix_〜.py`
- 処理は `base_train.py` の run() に引数として入れ、引数を渡さなければ今までどおり動くようにする(回帰テストで確認)
- 「効いた対策をほかの原因にも当てる」は時間があれば

### 対策の一覧(すべて完了)

| 対策 | 実装 | ファイル |
|---|---|---|
| 早期終了 | run() に `patience`・`min_delta`、best の ckpt を保存して読み込む | `fix_early_stop.py` |
| weight decay | 引数だけ(0.1) | `fix_weight_decay.py` |
| データ増量 | train_frac 0.3 / 1.0 | `fix_more_data.py` |
| モデルを縮める | d_model 64 / 32 | `fix_small_model.py` |
| Dropout | `dropout_model.py`(埋め込みの直後に nn.Dropout)、run() に `dropout` | `fix_dropout.py` |

### 結果(土台:train_frac 0.1・d_model 128)

| 対策 | val の最小値 | 判定 | 最終 val | 最終 gap | 効き方 |
|---|---|---|---|---|---|
| なし | 2.2484 / 1200 | 1950 | 2.4737 | 1.35 | ― |
| 早期終了(patience 5) | 2.2484(取り出す) | 1950 で停止 | ― | ― | 最小値の時点を取り出す。学習も短くなる |
| weight decay 0.1 | **2.2136** / 1650 | 2400 | 2.3790 | 1.21 | 最小値を下げ、過学習を遅らせる。効くのは後半 |
| Dropout 0.1 | 2.2364 / 1350 | 2100 | 2.3569 | 1.13 | 最小値はほぼ同じ。悪化を緩やかにする |
| Dropout 0.2 | 2.2378 / 1350 | 2100 | 2.2934 | 0.99 | 〃(p を上げるほど悪化が緩やか) |
| d_model 64 | 2.2909 / 2400 | 届かない | 2.3151 | 0.88 | 過学習は消えるが最小値は上がる |
| d_model 32 | 2.3488 / 3000 | 届かない | 2.3488 | 0.63 | 縮めすぎると未学習 |
| データ 0.3 | **2.0371** / 2850 | 届かない(横ばい) | 2.0600 | 0.65 | 一番効く。規則そのものが増える |
| データ 1.0 | **1.7112** / 3000 | 届かない(改善中) | 1.7112 | 0.19 | 〃 |

### 分かったこと

- 早期終了:最小値は下げない。止まるのは底ではなく、5回の不更新を確かめた時点(待ち時間 = patience × eval_interval)
- weight decay:重みの大きさに応じて 0 に引き戻し、丸暗記に必要な大きな重みを作りにくくする。最小値そのものを下げられる
- Dropout:前半は変わらず、後半の悪化だけを緩やかにする。「良い時点を長持ちさせる」。今回は埋め込みの直後の1か所だけ
- モデルを縮める:過学習と未学習のトレードオフ。最小値で比べると大きいモデル、最終値で比べるとちょうど良い大きさのモデルが勝つ
- データ増量:同じモデルでも、データ量で「過学習・横ばい・改善中」が分かれる。過学習するかは、モデルの大きさとデータ量の釣り合いで決まる。データが十分なら大きいモデルの方が良い(全データ:d64 1.83 / d128 1.71)
- weight decay・Dropout・モデルを縮めるは、どれも「丸暗記する力を弱める」対策。強すぎると学ぶ力まで弱める
- Dropout は学習中に乱数を使うので、学習バッチの並び(ix)も変わる。最小値の 0.01 程度の差はその影響も含む

## ステップ3:まとめ(完了)

### ブラインドテスト

| 問 | 状況 | 診断 | 対策 | 結果 |
|---|---|---|---|---|
| 1 | 底が高く早い(2.62 / iter 300)、train が 0.25、val が ln(65) を超える | データ不足の過学習 | 早期終了 → データ増量 → (増やせないなら)weight decay・Dropout | 7割 |
| 2 | gap 約 0.05 のまま、train も val も高止まり(2.18 / 2.23) | 未学習(モデルが小さい) | モデルを大きくする・正則化を弱める。過学習の対策は逆効果 | 8割 |
| 3 | gap は 0.03 → 0.17 と開くが、val は下がり続け、最後に1点だけ +0.002 | 順調(過学習ではない) | 止めずに学習を延ばす。Dropout は不要 | 9割 |

### 診断の流れ

1. まず val CE の最小値と、そのあとの動きを見る。最終値だけでは判断しない
2. 過学習は「最小値を5回続けて更新せず、かつ最小値より 0.02 以上悪化した」ときに判定する。gap が開くだけでは過学習と言わない
3. 過学習なら、底の高さと位置で原因を見分ける。底が高く早く、train が丸暗記の水準まで下がるならデータ不足。底は低いがその後上がるならモデルが大きすぎる
4. 過学習なら丸暗記を抑える対策(データ増量・weight decay・Dropout・モデルを縮める)、未学習なら逆に学ぶ力を増やす対策(モデルを大きくする・正則化を弱める)を選ぶ
5. 曲線がずっと下がっていることが成功とは限らない。どちらの場合も早期終了を入れ、val が最小になった時点のモデルを残すのが一番良い

### 補足:判定基準の2つの条件

- `patience`(5回):どれだけ長く改善しないか。1点だけの上下で止めないため
- `min_delta`(0.02 = ノイズ 0.004 × 5倍):どれだけ大きく悪化したか。誤差の範囲の悪化で止めないため
- 回数の5と倍率の5は別々に決めた値
