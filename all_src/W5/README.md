## 共通のルール

### 過学習の判定基準

- val CE の最小値を更新しない評価点が **5回** 続き、かつ
- 現在の val CE が最小値より **0.02以上** 高い(ノイズ 0.004 の5倍)

ステップ2の早期終了(patience)にもそのまま使う。

### 物差し

- 主は CE、正解率は副。判定と比較は CE で行う
- 記事で見せるときは PPL(= exp(CE))を併記してもよい
- 記録する項目:val 最小値 / val 最小の iter / そのときの gap / 最終 val / エポック数

### エポック数

- 1 iter で見る文字数 = batch_size × block_size = 32 × 32 = 1,024
- エポック数 = max_iters × 1,024 ÷ 学習データの文字数

### #4 特徴量が多すぎる(案B)

**ねらい**:各サンプルに「テキストのどのあたりから切り出したか」の番号(区間ID = 開始位置 ÷ 1,000)を付けて入力に足す。train では丸暗記の手がかりになるが、val では内容と対応しないので役に立たない。

**決めたこと**

- 区間IDは1サンプルに1つ。埋め込み (B, d) を (B, 1, d) にして、32文字すべてに同じベクトルを足す
- val にも val 内の開始位置から区間IDを付ける
- 区間の数 = train と val の長いほう ÷ 区間の幅 + 1(幅 1,000 なら 112)
- W2 の `model.py` は変えず、継承した FeatureModel を `feat_model.py` に作る

## ここまでで分かったこと

- 「gap が開く」ことと「val が上がる」ことは別。過学習と判断するのは後者
- val が1点だけ上がることはある。1点の上昇だけでは過学習と判断しない
- データが少ないほど、val の底は高く・早く来て、底の後の悪化も急になる
- 「1エポックで底を打つ」という仮説は外れ。実際は 24〜46 エポックまで val は改善した。よく出る規則を学び尽くしてから、特定の並びの丸暗記が始まる
- d_model を上げると、底は低く・早く来るが、その後の悪化が速い。ちょうど良いところで止めれば、大きいモデルの方が良い
- 過学習すると、val acc は横ばいのまま val CE だけが上がる(自信満々の間違い)。0.01 では学習前やでたらめ(ln 65)より悪くなった
- 回帰テスト:コードを変えるたびに、前と同じ設定で完全一致するかを確かめる。一致すれば、その変更が学習に影響していないと言える
