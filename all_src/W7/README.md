# W7:出口を動作に差し替える

## 目的

Physical AI の入口に立つ。

W2 の胴体(`Block`)は変えずに、出口を「次の文字」から「次の動き(連続値)」に差し替える。
2D 平面上の点がお手本を真似して目標へ動くポリシーを作り、**ロールアウトで破綻するところを観察する**。

**環境を凝らない。点が動けば目的は達成。**

## これまでの週とのつながり

| 週 | 入口 | 胴体 | 出口 |
|---|---|---|---|
| W2 | 文字 → 埋め込み | `Block` ×4 | 次の文字(softmax + CE) |
| W4 | 同上 | 同上 | 分類(CE)/回帰(MSE)を比較 |
| W6 | 画像パッチ → `Linear` | 同上 | 10クラス分類 |
| W7 | 各時刻の状態 → `Linear` | 同上 | 各時刻の行動 `(dx, dy)`(回帰) |

## 前段階:W7 の言葉を W2 に置き換える

| W7 の言葉 | 意味 | W2 で対応するもの |
|---|---|---|
| 状態(state) | いま点がどこにいて、周りがどうなっているか | 入力の文字 |
| 行動(action) | 次の1歩でどれだけ動くか `(dx, dy)` | 次の文字 |
| 方策・ポリシー(policy) | 状態を受け取って行動を返すモデル | `GPTMini` |
| お手本(expert) | 正解の行動を出すルールベースの制御器 | tiny_shakespeare の本文 |
| 軌跡(trajectory) | 状態と行動を1エピソード分並べたもの | 1つの文章 |
| 行動クローニング(BC) | お手本の「状態→行動」を教師あり学習で真似させる | 次の文字予測の学習(teacher forcing) |
| ロールアウト | 学習したモデル自身に行動させ、環境を進めていく | 生成(`generate`)。予測した文字を `torch.cat` で入力に戻す |

### ロールアウトで壊れる理由(W2 の生成で考える)

- 学習中、モデルは本物の本文から切り出した並びしか入力として見ていない(`get_batch`)
- 生成中に一度間違えると、その文字は入力に残り続け、モデルは学習中に見たことがない入力から予測することになる(block_size = 32 なら32回分残り、押し出されても影響を受けた文字が残る)
- 生成中は参照(forward)だけで重みは直らないので、間違えてもその場で修正できない
- その結果、間違いが積み重なり、後ろに行くほど崩れやすくなる
- 名前:分布シフト(exposure bias)、compounding error

## W2 の `Block` の復習

- 入出力は `(B, T, d_model)` で、形は変わらない(W2:`(B, 32, 64)`)。だから縦に積めて、入口を差し替えればそのまま使える
- Pre-LN:
  ```python
  x = x + self.attn(self.ln1(x))   # W2 のコードでは a, _, _ = self.attn(self.ln1(x)); x = x + a
  x = x + self.ffn(self.ln2(x))
  ```
- Post-LN:
  ```python
  x = self.ln1(x + self.attn(x))
  x = self.ln2(x + self.ffn(x))
  ```
- Pre-LN には `x` が何も通らずに進む近道がある。Post-LN は4ブロックで `ln` を8回通る。W2 の勾配:Pre-LN 約 7.91e+01、Post-LN 約 1.95e-07
- 位置埋め込みは `Block` の外(入口)で足す。W2 は何文字目か、W6 は何番目のパッチか、W7 は何番目の時刻か
- block_size は T の上限。三角行列は block_size × block_size(32×32)を1つ持ち、`self.tril[:T, :T]` で切り出す
- T > block_size のとき:
  - `GPTMini` 全体に渡す → 入口の位置埋め込みで止まる(表が32行しかない)
  - `Block` だけに渡す → `tril[:40, :40]` は黙って 32×32 を返し、`masked_fill` で 40×40 と形が合わずエラー
- `idx[:, -block_size:]` は後ろの32個だけを残す。いまの状態+31ステップ前まで
