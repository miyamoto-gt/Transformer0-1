# W3: 壊して症状を観察する

W2で作ったGPTMiniを意図的に壊し、「どんなバグがどんな症状として現れるか」を
症状ベースの表にまとめた。

## 方針

- **W2のコードは書き換えない。** `sys.path` に `all_src/W2` を追加し、
  `model.py` と `data_utils.py` を import して使うだけ。
  構造を壊す場合も、W2のクラスを継承するか、モデル作成後に buffer を
  書き換える。
- **データは tiny_shakespeare のまま。** 変えるものを1つだけにするため。
- **全実験を 600 iter / 25 iter ごとの記録で統一。** 当初は 200 iter で
  始めたが、#3 が 325 iter まで基準と区別できなかったため 600 に変更した
  (後述)。

```
all_src/
  W2/                      ← 読むだけ。編集しない
    model.py               GPTMini
    block.py               Block(attn + ffn + LayerNorm + 残差)
    attention.py / ffn.py / layernorm.py
    data_utils.py          load_data, get_batch
    data/input.txt         tiny_shakespeare
  W3/
    common.py              共通処理。import しても何も実行されない
    broken.py              壊したクラスの定義(BlockNoResidual)
    standard.py            基準
    break_lr.py            #1 学習率過大
    break_shuffle.py       #2 targets シャッフル
    break_mask.py          #3 causal mask 削除
    break_init.py          #4 初期値 ×10
    break_residual.py      #5 residual 削除
    break_overfit.py       #6 データを2000文字に限定
    check_batch.py         x と y の対応を目視する
    check_grad.py          層別の勾配ノルムを比べる
    check_attn.py          t+1 へのAttentionの重みを測る
    compare_mask.py        基準と #3 の loss を重ねて描く
    compare_attn.py        loss とAttentionの重みを2軸で描く
    docs/                  グラフの出力先
```

各実験ファイルは `common.build_model()` → 1か所だけ壊す →
`common.run()` の3ステップだけ。差分が1行で見えるようにしてある。

## 変数

| 変数 | 値 | 意味 |
|---|---|---|
| `V` | 65 | 文字の種類数(語彙サイズ) |
| `d_model` | 64 | 1文字を表すベクトルの次元 |
| `block_size` | 128 | 一度に見る文字数(文脈の長さ) |
| `batch_size` | 32 | 同時に処理する文章の本数 |
| `n_layer` | 4 | Blockの数 |
| `n_head` | 4 | attentionのヘッド数(`Block` の既定値) |
| `lr` | 1e-3 | 学習率(AdamW) |
| `max_iters` | 600 | 学習回数 |
| `eval_interval` | 25 | ログを取る間隔 |
| `eval_iters` | 20 | loss の平均を取るバッチ数 |
| seed | 1337 | `build_model()` 内で固定。条件間で初期重みを揃える |

データは先頭90%が train(1,003,854文字)、残り10%が val(111,540文字)。
train は重みの更新に使い、val は測るだけで学習には一切使わない。

`eval_iters` が20あるのは、1バッチだけだと取れた箇所の難易度でブレるため。
20バッチの平均でばらつきが約 1/√20 に抑えられる。W3 は 0.01 単位の差を
比べるので、この精度が必要になる。

## アーキテクチャ

```
入力  x : (32, 128)                    batch × 文字数(整数ID)
        │
        ├─ tok_emb : Embedding(65, 64)      文字 → ベクトル
        └─ pos_emb : Embedding(128, 64)     位置 → ベクトル
        │  (足し合わせる)
        ▼
      (32, 128, 64)
        │
┌───────┴────────────────────────────────┐
│  Block × 4                             │
│                                        │
│    x ──┬── ln1 → attn(4 head) ──┐      │  Pre-LN
│        └──────────────(+)◀──────┘      │  残差
│        │                               │
│    x ──┬── ln2 → ffn ───────────┐      │
│        └──────────────(+)◀──────┘      │
│                                        │
└───────┬────────────────────────────────┘
        ▼
      (32, 128, 64)
        │
        ├─ 最終 LayerNorm
        ▼
      lm_head : Linear(64 → 65)
        │
        ▼
    logits : (32, 128, 65)               各位置で次の文字の予測
        │
        ▼
    softmax → 確率 → 正解との交差エントロピー = loss
```

`x` は「その位置についてモデルが現時点で持っている理解」。層を通るたびに
情報が足されて、最後に予測へ変換される。

### #3 と #5 が壊す場所は別

同じ1行の中の、違う部分を壊している。

```python
x = x + attn(ln1(x))
    ↑       ↑
    #5      #3
```

| | attention の中 | 残差の足し算 | 見える範囲 |
|---|---|---|---|
| 基準 | 正常 | あり | 過去のみ |
| #3 | mask 無効 | **あり** | **全体** |
| #5 | **正常** | なし | 過去のみ |

#3 は attention の内部(`masked_fill`)を無効にし、#5 は attention の外側の
配線(`x +`)を外した。症状も正反対になる。

### x と y の関係

`y` は `x` を1文字ずらしたもの。位置 t では `x[0..t]` を見て `y[t]` を当てる。
128文字ぶんの予測問題が1本の文章から取れる。

```
x: '\nANGELO:\nAnd she wil'
y:  'ANGELO:\nAnd she will'
```

`y[t]` は `x[t+1]` と同じ文字。**これが #3 が成立する理由**で、mask を外すと
答えが入力の中に見えてしまう。

### Pre-LN と Post-LN

`Block` は `pre_ln` で切り替わる(W2で検証済み。W3では Pre-LN 固定)。

```python
# Pre-LN (既定)          正規化してから計算し、元の x に足す
x = x + attn(ln1(x))
x = x + ffn(ln2(x))

# Post-LN                足してから正規化する
x = ln1(x + attn(x))
x = ln2(x + ffn(x))
```

LayerNorm の位置(Pre/Post)と残差の有無(`x +` があるか)は独立した設計要素。
#5 で壊すのは後者だけで、Pre-LN のままにしてある。

### パラメータ配分(合計 215,873)

| 部位 | 数 |
|---|---|
| tok_emb (65×64) | 4,160 |
| pos_emb (128×64) | 8,192 |
| Block × 4 | 約 199,168(1層あたり約 49,792) |
| 最終 LayerNorm | 128 |
| lm_head (64×65 + 65) | 4,225 |

9割以上が Block にある。

> **Attention:** W2の記録にある 193,089 は古い値。現行の `model.py` は
> `Block(d_model, block_size)` と呼び出しており、`Block` の既定値
> `n_head=4` が使われるため 215,873 になる。W3の基準は 215,873。

## 4つの物差し

判断の基準になる値。これらからどれだけ離れているかで症状を読む。

| 物差し | 値 | 意味 |
|---|---|---|
| `ln(V)` | 4.174 | 何も知らないモデルの loss |
| **ユニグラム水準** | **約 3.30** | 文字の出現頻度だけを覚えた loss |
| `1/V` | 0.0154 | 一様に予測したときの最大確率 |
| logits std | 0 | 完全に一様なときの出力のばらつき |

`ln(65) = 4.174` は、65文字すべてに同じ確率 1/65 を割り当てたときの
交差エントロピー。**これより上 = でたらめより悪い**。

**3.30 は W3 で実測から発見した物差し。** #2・#5、そして #1(lr=1.0)が
いずれもここで停滞した。`lm_head.bias` が担当する「文字の出現頻度」だけを
学んだ状態で、文脈依存の規則(3.30 → 2.24 の区間)を学べていないことを示す。

```
13.7   #4 の初期値(でたらめの1万分の1以下の確率)
 4.174 ln(V)   何も知らない
 3.30  ユニグラム   文字の頻度のみ   ← #1(lr=1.0), #2, #5 がここで停滞
 2.24  基準の600 iter到達点   文脈依存の規則あり
 1.83  W2 の 3000 iter 到達点
 0.05  #3(mask削除)   カンニングによる偽の低さ
```

## 症状 → 原因の対応表

### #1 学習率過大

| | lr = 0.1 | lr = 1.0 |
|---|---|---|
| 症状 | iter 175 で底(2.9313)、以降 2.9〜3.03 で停滞 | iter 25 で 210 に跳ね、250 で 215 のピーク、以降減衰 |
| 600 iter | 2.9645 | 3.3410(ユニグラム水準) |
| 発見しやすさ | **低い**(下がっているように見える) | 高い(一目で異常) |

**原因:** 学習率が大きすぎて最小値を通り越す。
**確認方法:** 終盤の傾きが上向き・横ばいでないか。初期値を測って
初期化の問題と切り分ける(どちらも init loss は基準と同一の 4.3254)。
**修正:** 学習率を下げる。勾配クリッピング。

lr=1.0 は 215 まで暴走した後に減衰し、最終的にユニグラム水準へ「復帰」した。
iter 600 の値(3.34)だけ見ると #2・#5 と区別できないが、途中の暴走を
見れば明らか。**打ち切る位置で結論が変わる例。**

AdamW が勾配を正規化するため、NaN には至らなかった。**「発散 = NaN」と
思い込んでいると見落とす。振動もまた発散の形。**

### #2 targets シャッフル

**症状:** iter 50 で 3.36 に達した後、550 iter のあいだ小数第2位まで動かない。
**観測値:** iter 50 → 600 で 3.3616 → 3.3403。基準は同区間で 2.86 → 2.24。
**原因:** `y` をバッチ内で入れ替え、入力と正解の対応が壊れている。
学習できるのは文字の出現頻度だけ。
**確認方法:** `check_batch.py` で x と y をデコードして目視する。

```
正常     : x '\nANGELO:\nAnd she wil'  →  y 'ANGELO:\nAnd she will'
シャッフル: x '\nANGELO:\nAnd she wil'  →  y 't know it.\n\nCORIOLAN'
```

ANGELO のセリフを見せて「次は CORIOLANUS の台詞だ」と教えている状態。
**エラーは一切出ない。** コードは正常に動き、loss も下がり、学習も進む。
ただ何も学べないだけ。

**修正:** シフト・対応付けを見直す。

### #3 causal mask 削除 ★W3で最も重要

**症状:** iter 325 まで基準と完全に一致。そこから崩れ落ちるように低下し、
600 iter で 0.0472(基準の 1/47)。**train も val も下がり続け、2本は重なったまま。**

| iter | 基準 | #3 loss | #3 attn→t+1 |
|---|---|---|---|
| 0 | 4.3257 | 4.3258 | 0.0078(一様) |
| 100 | 2.6113 | 2.6065 | 0.0084 |
| 200 | 2.5144 | 2.5033 | 0.0102(1.3倍) |
| **300** | **2.4400** | **2.4320** | **0.0195(2.5倍)** |
| 325 | 2.4245 | 2.3914 | 0.0336 |
| 350 | 2.4174 | 2.1935 ← 分岐 | 0.0683 |
| 400 | 2.3941 | 1.0645 | 0.1855 |
| 600 | 2.2395 | **0.0480** | **0.2770(35倍)** |

**原因:** `mask.fill_(True)` により、位置 t が `x[t+1]` を参照可能。
`y[t] = x[t+1]` なので、答えが入力に含まれている。

**なぜ325 iterも潜伏するか — 測定で確認した。**

`attn→t+1` は「位置 t が位置 t+1 に向けるAttentionの重み」の平均
(`common.attn_to_next`)。mask がある基準では常に 0、mask なしの学習前は
0.00778 で 1/128 = 0.0078125 とほぼ完全に一致する。つまり**外した直後は
完全に一様**で、答えは他の127個に埋もれていて信号にならない。
学習前の loss 差も 4.319901 vs 4.319870 とほぼゼロだった。

そこから「位置+1を見る」重み付けが育っていく。伸び方は非線形。

| 区間 | attn の伸び |
|---|---|
| 0→100 | ×1.08 |
| 100→200 | ×1.21 |
| 200→300 | ×1.91 |
| **300→400** | **×9.5** ← 自己増強 |
| 400→600 | ×1.49(飽和) |

**iter 300 の時点で attn はすでに2.5倍に育っているのに、loss は基準と
ほぼ同じ 2.4320(基準 2.4400)。** グラフ上ではまったく区別できない。
`docs/compare_attn.png` は、赤(attn)の立ち上がりが青(loss)の崩壊に
先行していることを2軸で示したもの。

**確認方法:生成させるしかない。** loss も val も正常に見えるため、
数値からは検出できない。

```
基準 (val 2.24)                          #3 (val 0.047)

Thes dreoun, hind youn ancorseshe be     H
fabuty, in thourd sowe therds            HHVe
ineancoup ance theer wine, sonoule       HHHHLHH
tore, vet. sor's dintcrdlin thes         HL
kndd my agnat then anyou ans not         HHHH
doue the not moke nrall;                 HLN
I seld; Ther                             HHL
```

基準は `no` `four` `these` `wine` `not` `my` `then` といった実在語や
それに近い綴りを出し、カンマ・ピリオド・セミコロン、`I seld;` のような
1人称+セミコロンの構造も掴んでいる。#3 は `H` と改行の羅列で、
英語の構造を何も学んでいない。

生成時は未来が存在しないため、学習で身につけた「隣を見る」戦略が
一切使えない。文脈から次を予測する能力は**学ぶ必要がなかったので
学んでいない。**

**修正:** mask を戻す。

### #4 初期値 ×10

**症状:** init loss が ln(V) の3.3倍。急降下の後、基準に **追いつかないまま平行に遅れる。**

| | 基準 | #4 |
|---|---|---|
| init loss | 4.3254 | **13.7088** |
| logits std | 0.5767 | 5.7321 |
| max prob | 0.0522 | **0.7097**(一様の46倍) |
| iter 200 | 2.5144 | 2.7388(差 0.224) |
| iter 600 | 2.2395 | 2.4658(差 **0.226**) |

**400 iter 経っても差が縮まらない。** 初期値の悪さは一時的な遅れではなく、
最後まで残る。

loss 13.7 は「正解の文字に e^-13.7 ≈ 100万分の1 の確率しか置いていない」
という意味。ln(V) の3.3倍という数字より、確率で見ると1万分の1以下で
実際の悪さはずっと極端。

**原因:** `lm_head.weight` が大きすぎ、根拠なく特定の文字に確信している。
**確認方法:** 学習前に init loss / logits std / max prob を測り、
ln(V) / 0 / (1/V) と比べる。
**修正:** 出力層を小さく初期化する。

なお init loss は測るたびに振れる(18.39 / 13.71)。logits が極端に尖って
いるため「たまたま当たったか外れたか」で大きく動く。一方 logits std は
5.77 / 5.73 と安定していた。**モデルの性質(std)は安定、データ次第の
結果(loss)は不安定。**

### #5 residual 削除

**症状:** #2 とほぼ同一の曲線。iter 25 で 3.37、600 iter でも 3.3432。

| iter | #2 シャッフル | #5 残差削除 |
|---|---|---|
| 200 | 3.3384 | 3.3513 |
| 400 | 3.3389 | 3.3663 |
| 600 | 3.3403 | 3.3432 |

**原因:** `x = x + attn(...)` を `x = attn(...)` に変えた。各層が前の層の
理解に「追記」するのではなく「上書き」する。attention は重み付き平均なので、
通すたびに位置固有の情報が薄まる。逆方向では、足し算の微分=1 による
勾配の素通り経路が失われる。

**確認方法:層別の勾配ノルム。**

| 条件 | block0 | block1 | block2 | block3 | 形 |
|---|---|---|---|---|---|
| 基準 | 0.3706 | 0.3622 | 0.3702 | 0.3749 | 均一 |
| #2 | 0.3547 | 0.3504 | 0.3622 | 0.3657 | 均一 |
| **#5** | 1.8481 | 3.2803 | 4.2306 | **5.2668** | **階段状** |

出力側に向かって約1.8倍ずつ増える。基準が揃うのは残差が素通り経路を
作るため。

**勾配が5〜14倍あるのに学習は止まる。** Adam が勾配の大きさを正規化する
ので、問題は勾配ではなく順方向で情報が積み上がらない構造そのもの。
勾配の異常は原因ではなく目印。

到達した 3.29 は `lm_head.bias` が担当する出現頻度の水準。**失われたのは
文字同士の関係性(3.30 → 2.24 の区間)** であって、頻度ではない。

**修正:** 残差接続を戻す。

**予想との差:** 「4層と浅いので影響は小さい」と予想したが外れた。
4層でも積み上げは必須。

### #6 データを2000文字に限定

**症状:W3で唯一、train と val が分離する。**

| iter | train | val |
|---|---|---|
| 0 | 4.3421 | 4.3257 |
| **75** | 2.4180 | **2.9865**(底) |
| 200 | 2.0452 | 3.1918 |
| 400 | 1.0100 | 4.1533(ln(V)を突破) |
| 600 | **0.2456** | **5.7113**(差 5.47) |

**原因:** train 2,000文字に対しパラメータ 215,873個。開始位置は1,872通りしか
なく、600 iter × batch 32 = 19,200サンプルで平均10回以上同じ箇所を見る。
暗記が成立する。

**Attention:** `estimate_loss` にも同じ 2,000文字を渡さないと、train の線が
「学習に使っていない100万文字」を測ることになり、過学習が測れない
(最初この誤りで両方上昇するグラフが出た)。

**確認方法:** train/val の乖離。生成文に学習データの断片が出る。

```
Al:
Speak.

Fitorst Citirizen:
You are all resolveratice tive the ous d:
```

`All:` `Speak.` `First Citizen:` `You are all resolved...` は
tiny_shakespeare の冒頭そのもの。一見「基準より英語らしい」が、中身は丸写し。

**修正:** データを増やす。iter 75 で早期終了する。正則化。

## 診断フローチャート

```
loss が 3.3 付近で停滞している
  │
  ├─ 1. check_batch.py で x と y を目視      ← 1秒。最も安い
  │     対応が壊れている → #2(データのバグ)
  │     対応が正常 → 次へ
  │
  ├─ 2. check_grad.py で層別の勾配を測る
  │     階段状 → #5(構造のバグ)
  │     均一   → 次へ
  │
  └─ 3. 学習曲線の全体を見る
        途中で暴走していた → #1(学習率過大からの復帰)
```

loss が下がり続けている場合も安心はできない。

```
loss が順調に下がっている
  │
  ├─ val も下がっているか
  │     val だけ上がる → #6(過学習)
  │     両方下がる → 次へ
  │
  └─ 生成させてみる                          ← これしか方法がない
        文章が壊れている → #3(mask のバグ)
```

原則は **安いものから**。データの目視は1秒、勾配の測定は数秒、
内部の観察は実装が必要。

## 分かったこと

**1. 症状が同じでも原因は別々。** #2(データ)と #5(構造)は曲線が区別できない。
追加の測定(層別の勾配)を1つ足して初めて切り分けられる。#1 の lr=1.0 も
最終値だけ見れば同じ 3.3 に見える。

**2. train と val が重なっていても壊れている。** 6実験のうち分離したのは
#6 だけ。「val を見ていれば安心」は成り立たない。

**3. loss が低いほど良いとは限らない。** #3 は基準の 1/47 の loss を
達成しながら、生成文は基準より明確に劣る。数値に一切の異常が出ない。

**4. 打ち切る位置で結論が変わる。** #3 は 325 iter まで基準と一致し、
200 iter で打ち切れば「影響なし」と誤断する。#1 の lr=1.0 も 200 では
「振動」、600 では「暴走後にユニグラム水準へ復帰」と読みが変わる。

**5. loss が平らでも内部は動いている。** #3 の attn→t+1 は iter 200〜300 の
「何も起きていない」区間で 1.3倍 → 2.5倍と育っていた。学習が止まったように
見えても、内部で回路が組み上がっていることがある。

**6. 初期値の影響は最後まで残る。** #4 は 600 iter でも基準に 0.226 負けた
まま(200 iter 時点の差 0.224 とほぼ同じ)。縮まらない。

**7. 初期 loss は既定初期化のままが最良だった。** 下記参照。

## 初期値の実験(#4 の対照実験)

`lm_head` の初期化を変えて、init loss を理想値 4.174 に近づけた場合。
この3条件のみ 200 iter での比較(#4 に入る前の予備実験のため)。

| 条件 | init loss | logits std | max prob | iter 200 |
|---|---|---|---|---|
| 基準(既定初期化) | 4.3254 | 0.5767 | 0.0522 | **2.4977** |
| `weight ×0.01` | 4.1811 | 0.0705 | 0.0173 | 2.5280 |
| `weight ×0.01 + bias.zero_()` | **4.1742** | **0.0057** | **0.0156** | 2.5277 |
| `weight ×10`(#4) | 13.7088 | 5.7321 | 0.7097 | 2.7076 |

- 学習前のモデルは一様ではない。`Linear` の既定初期化(一様分布
  U(-1/√64, 1/√64))により logits に std 0.577 のばらつきが出て、
  最大確率が一様の3.4倍になる。**バグではなく既定初期化の素直な結果。**
- `weight` のみ ×0.01 では std が 0.0705 残る。`bias` を縮小していないため。
  `bias.zero_()` を足すと 0.0057 まで落ち、init loss が ln(V) に一致する。
- **init loss を理想値にしても、学習は速くならない。** むしろ基準より
  わずかに遅い(2.5277 vs 2.4977)。
- Karpathy の recipe が「初期 loss を確認せよ」と言うのは **異常検知のため**
  であって性能向上のためではない。+0.15 の上振れは異常ではなかった。

再現するには `break_init.py` の `SCALE` を 0.01 にし、`bias.zero_()` を
1行足す(専用スクリプトは削除済み)。
